# Published Pi CLI resolution

Delegate 0.2.15 reads the installed `@earendil-works/pi-coding-agent` manifest's `bin.pi`. It no longer guesses `dist/cli.js`. The Pi 1.0.0 package publishes `dist/bundle/cli.js`; the internal `dist/cli.js` still exists, so this change corrects contract selection rather than a demonstrated missing-file error.

## Resolution boundary

Order remains explicit `PI_DELEGATE_CLI`, adjacent package, global Bun package roots, executable `pi` on PATH, then the existing literal `pi` fallback. Package discovery uses ESM resolution; if `package.json` is export-hidden, it locates the nearest manifest above the public root without importing package code. The manifest must have the exact package name and a non-empty `bin.pi`. The bin must be a regular file whose normalised and real paths remain inside the package. Internal symlinks and linked package roots work; escaping symlinks do not.

Valid older manifests naming `dist/cli.js` work unchanged. Invalid candidates fall through without guessing a private path. The explicit override/PATH fallbacks retain their previous behaviour; they do not pin a version or prove archive provenance. Operator-installed package code remains trusted, and same-UID replacement after validation is outside this path check.

## Tests

`cli-manifest.test.ts` covers bundled/legacy/relative bins, malformed metadata, wrong package names, absent/non-file bins, absolute/traversing paths, symlink containment, export-hidden manifests and resolver precedence. Existing selection, approval, exclusions, explicit-tier behaviour, process handling and output tests remain unchanged.

`cli-100.test.ts` is an opt-in real-package check. It requires an explicit package directory and archive, a separate Linux network namespace and the ordinary repository filesystem-isolation preload. It verifies the archive's SHA-512 against the earlier exact 1.0.0 registry receipt and compares the package manifest plus all 73 bundled JS files byte-for-byte. A standalone copy of Delegate resolves the installed package through normal lookup and invokes its public bin under Bun with `--offline --version`, an allowlisted environment and empty profile/workspace. Both directories must remain empty. The repository preload isolates the test runner; children receive explicitly constructed temporary paths and do not load that preload. This is neither a filesystem sandbox nor a malicious-package execution test.

The 2 October 2026 run reported one test and 160 `expect()` calls under Bun 1.4.2. The first attempt counted only top-level bundle files and failed before CLI execution; recursive enumeration corrected the fixture. No credential/provider/MCP operation was run. This is package-resolution/version evidence only; it does not qualify inference, authentication, refresh/logout, environment scoping in normal delegation or selected-engine parity. The old 0.87.1 receipts are unchanged.

Run normal resolver tests from the repository root:

```sh
bun test addons/delegate/cli-manifest.test.ts addons/delegate/index.test.ts
```

For the real-package check, use a separately provisioned loopback-only network namespace, drop its capabilities and set these non-secret inputs before invoking `bun test addons/delegate/cli-100.test.ts`:

- `PICLAW_E2E_DISPOSABLE=1`
- `PICLAW_DELEGATE_100_PACKAGE`: absolute path to the exact package directory
- `PICLAW_DELEGATE_100_ARCHIVE`: absolute path to the verified npm archive
- `PICLAW_DELEGATE_PARENT_NETNS`: the parent `/proc/self/ns/net` identity, captured before entering the namespace

The ordinary compatibility command skips that real-package case when inputs are absent. Source-version pins in the repository stay unchanged; they are not relabelled as Pi 1.0.0 qualification.

Standalone imports and package-builder tests passed 35 tests / 58 `expect()` calls. All five compatibility TypeScript projects passed using Bun to run the compiler. Catalogue validation and package dry-run passed; a temporary public-builder tarball imported outside the repository with the resolver/entrypoint/compat/manifest bytes unchanged.

The initial compatibility run failed two unchanged A2A cases (a 5-second store timeout and a late delivery-count assertion). Their isolated suite passed 73 tests with eight opt-in skips; the complete unchanged compatibility rerun then passed. These failures are retained in the local logs under `/workspace/tmp/delegate-pi100-cli/`. No A2A code or timeout changed. Independent narrow resolver review found no blocker; a broader review timed out and supplied no approval. Fixture review prompted the explicit child-filesystem-scope clarification above.

## Release boundary

The version/catalog change prepares a candidate only. Merging this repository's add-on changes can trigger public package publication; merge and release require separate approval. No archive is deployed or installed by these checks.
